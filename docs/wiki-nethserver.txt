======ClamAV======
[[https://www.clamav.net/|ClamAV]] is the open-source antivirus engine used by mail gateways, file servers and web applications to scan files for malware. This module runs the ClamAV daemon as a **scan service for the cluster**: Nextcloud's //Antivirus for files// app, ecoDMS, Samba or any other client that speaks the clamd protocol connects to it over TCP 3310.

ClamAV is a community application from the [[ns8:tebbiworld_repository|tebbiworld]] repository. Documentation and source can be found on [[https://github.com/tebbiworld/ns8-clamav|Github]]

=====What it does=====
The NS8 Mail module ships its own clamd, but bound to ''127.0.0.1:11330'' of the mail node only — unusable for a Nextcloud on another node. This module runs the official ''clamav/clamav'' image (Cisco Talos) wherever it is needed and is reachable from every node of the cluster through the cluster VPN.

  * clamd on TCP 3310 in the host network, with freshclam keeping the signatures current
  * reachable from modules on the same node, from every node via the cluster VPN, and optionally from the LAN
  * scan limits (file size, scan size, stream length) and the update schedule as settings
  * live status on the settings page: engine and signature database version

=====Architecture=====
One rootless container from the pinned official image, plus an optional second one for the web/REST front end.

^ ^ ^
| Port | TCP 3310 on all addresses of the node (host network) |
| Volume ''clamav-db'' | signature database (~300 MB), refreshed by freshclam; not in the backup, re-downloaded when missing |
| Memory | clamd keeps the signatures in RAM — plan **about 1 GB** for the node |

Who can connect is decided by the node firewall, not by the module:

^ Client ^ Address to use ^ Allowed ^
| Module on the same node, slirp4netns network (NS8 Nextcloud) | ''10.0.2.2:3310'' | always |
| Module on the same node, pasta network | ''host.containers.internal:3310'' | always |
| Module or service on another node | ''<VPN address of this node>:3310'' (10.5.4.x, zone //trusted//) | always |
| Clients in the LAN | ''<LAN address>:3310'' | only with **LAN access** enabled (opens 3310/tcp in the public zone) |

One instance per node (fixed port). The Mail module's clamd on 11330 does not clash.

=====Installation=====
On the NethServer 8 cluster leader:

<code bash>
add-module ghcr.io/tebbiworld/clamav:1.1.0 1
</code>

Configure it (all settings have defaults; this keeps the LAN closed):

<code bash>
api-cli run module/clamav1/configure-module --data '{
  "listen_lan": false,
  "max_file_size_mb": 100,
  "max_scan_size_mb": 400,
  "stream_max_length_mb": 100,
  "signature_checks_per_day": 12
}'
</code>

The first start unpacks the signature database; clamd answers after a minute or two, and the settings page then shows engine and signature version together with the addresses clients should use.

=====Settings=====

^ Setting ^ clamd option ^ Default ^
| LAN access | firewall public service ''3310/tcp'' | off |
| Maximum file size (MB) | ''MaxFileSize'' — larger files are not scanned | 100 |
| Maximum scan size (MB) | ''MaxScanSize'' — data scanned per file including unpacked archives | 400 |
| Maximum stream length (MB) | ''StreamMaxLength'' — largest file a client may stream; not smaller than the maximum file size | 100 |
| Signature update checks per day | ''freshclam --checks'' | 12 |

=====Nextcloud=====
Install the app //Antivirus for files// (''files_antivirus''), then under //Administration → Security → Antivirus for files//:

^ Field ^ Value ^
| Mode | **Daemon (host)** |
| Host | ''10.0.2.2'' if Nextcloud runs on the same node as this module, otherwise the VPN address of the ClamAV node (shown on the settings page) |
| Port | ''3310'' |
| Maximum stream length | the module's value in bytes (default 100 MB = ''104857600'') |

Upload the [[https://www.eicar.org/download-anti-malware-testfile/|EICAR test file]] to confirm the connection: Nextcloud refuses it with a virus warning.

=====Using the scanner from other machines=====
The daemon speaks the plain clamd protocol on TCP 3310 — the same one Nextcloud uses — so any computer that reaches the port can use it, not only modules of the cluster.

====Requirements====
  * Switch on **LAN access** in the module settings. That opens 3310/tcp in the node firewall (public zone); the settings page then lists the LAN address to use. Without the switch only the node itself and the cluster VPN reach the daemon.
  * The clamd protocol has **no authentication and no encryption**. Anyone who can reach the port may submit files for scanning and could keep the daemon busy with large uploads. Enable LAN access only in a trusted network. Until the module offers an allow-list of its own, the source addresses can be restricted on the node with a firewalld rich rule for the service ''clamav1'' (replace the plain service opening by the rule).
  * Files are scanned as a **stream** (''INSTREAM''): the client sends the file contents to the daemon. The ''SCAN <path>'' command only works for paths the daemon sees inside its container, so it is useless from other machines. The stream size is limited by //Maximum stream length// (default 100 MB).

====Clients====
  * **ClamAV command line** (''clamdscan'' from the ClamAV package on Linux, macOS or Windows): a client configuration with the node address is enough, no local signatures are needed:
<code>
# clamd-remote.conf
TCPAddr <node address>
TCPSocket 3310
</code>
<code bash>
clamdscan --stream --config-file=clamd-remote.conf --fdpass=no /path/to/file
</code>
  * **Software with a clamd integration**: mail filters (rspamd, Amavis), proxies (Squid with c-icap), file servers (Samba ''vfs_virusfilter''), web applications with upload scanning, backup or ticket systems — configure them with host ''<node address>'', port ''3310'', mode "TCP" / "network daemon".
  * **Scripts**: the protocol is simple enough for a few lines of Python or PowerShell (send ''zINSTREAM\0'', then length-prefixed chunks, a zero-length chunk ends the file; the daemon answers ''stream: OK'' or ''stream: <signature> FOUND''). The module README contains a working Python example.

====Web / REST front end====
Since module version 1.1.0 the module can publish an **upload form and a JSON API** through Traefik: set a host name in the //Web / REST front end// section of the settings page together with a login name and password; Let's Encrypt, HTTP→HTTPS and an allow-list of client networks work as in the other modules.

^ ^ ^
| ''%%https://<host>/%%'' | upload form for one or more files, results as a table |
| ''POST /api/v1/scan'' | multipart field ''file'' (several allowed) or a raw body with header ''X-Filename''; JSON per file: ''clean'' / ''infected'' + signature / ''error'' |
| ''GET /api/v1/version'' | engine and signature database version |
| ''GET /api/v1/health'' | ''{"clamd":"up"}'' or 503 — no login, for monitoring |

<code bash>
curl -u scan:secret -F file=@invoice.pdf https://scan.example.org/api/v1/scan
</code>

Everything except ''/api/v1/health'' requires HTTP basic authentication. Uploads are streamed to clamd and never stored; the maximum size follows //Maximum stream length//. This is the way for users and systems without a clamd client — browsers, ''curl'', Windows scripts, web hooks.

=====Backup=====
The NS8 backup contains ''state/environment'' and ''state/clamav.env'' only. The signature database is not backed up on purpose; after a restore the container downloads it again.
